# QC2-034 — ApexLab Experiment Ledger

## Acceptance assessment

- **Result:** PASS
- The ledger records content-addressed, append-only budgets, preregistered experiments, comparison registrations, and chained trial events. Rejected trials and interrupted attempts remain in history and count toward the experiment cap. A resumed trial references its exact interruption event and checkpoint; prior resource usage and interruption records remain available for reporting.
- Resource usage and overrun labels are retained in trial events and aggregated by budget and experiment reports. Positive paid-cost budgets remain disabled until owner approval can be verified; this acceptance used zero-cost synthetic fixtures only.
- Holdout access attempts are immutable validation-owned records. A successful access consumes the dataset receipt; a later attempt is blocked and does not replace or erase that receipt. Denied attempts are retained without changing consumption state.
- PostgreSQL acceptance ran against a fresh local UTF8 database after applying migrations 0001–0005. It used actual configuration, ApexLab trainer, and validation session authorization. The trainer session was denied permission to delete an unfavorable trial event or update/delete a validation-owned receipt.
- No legacy source, production data, external dataset, or live execution was used.
